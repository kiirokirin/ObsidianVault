```
① まずAPIを使って最小構成で作る
        ↓
② アプリとしてちゃんと動くか確認
        ↓
③ APIが何をしているのか確認
        ↓
④ 「これ、端末内だけでできないか？」を検討
        ↓
⑤ できるならAPIなし版を試作
        ↓
⑥ 性能・速度・容量・開発難易度を比較
        ↓
⑦ 良い方を採用
```

例えば画像処理アプリなら、

```
API版
iPhone → API → 処理結果
```

をまず作る。

その後、

```
APIなし版
iPhone → iPhone内部で処理 → 結果
```

を試してみる。

APIなし版が十分使えるなら、こちらの方が

- API料金が発生しない
- APIの突然の仕様変更に影響されにくい
- APIサービス終了の影響を受けない
- 通信が不要
- オフラインでも動かせる
- ユーザーデータを外部に送らずに済む

というメリットがあります。

ただし、**AIのように端末内で処理するのが重いものはAPI版の方が圧倒的に簡単・高性能**という場合もあります。

なので、個人開発なら、

**「まずAPIで動くものを作る → APIなしにできるか試す → 無理ならAPI版を採用」**

くらいが一番現実的です。

そしてもう一つ重要なのが、最初からコードを

```
アプリ本体
  ↓
処理部分
  ↓
API
```

のように分離しておくことです。

そうすると後から、

```
処理部分 → API
```

を

```
処理部分 → iPhone内の処理
```

に交換しやすくなります。

これはAIにアプリを作らせる場合にもかなり重要な設計方針です。
