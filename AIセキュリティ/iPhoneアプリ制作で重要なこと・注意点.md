## 基本方針

まず考えるのは、**「iPhone内だけで完結するのか、外部サービスを使うのか」**。

```
iPhoneだけで完結
→ 比較的シンプル・安全

iPhone
 ↓
外部API
 ↓
結果
→ APIの管理が必要

iPhone
 ↓
自分のサーバー
 ↓
AI API・データベース
→ セキュリティ対策がかなり重要
```

AppleのApp Store審査があるので、Webサービスを直接公開するよりは管理しやすい。ただし、**App Store審査＝アプリ全体の安全性をAppleが保証する、ではない**。

---

## APIを使う場合

特に確認するのは、

- APIに何のデータを送るか
- 送ったデータが保存されるか
- AIの学習に利用されるか
- 利用規約・プライバシーポリシー
- APIの料金
- 利用回数制限
- API停止時の動作

特にAI APIでは、**個人情報・パスワード・クレジットカード情報などを不用意に送らない**。

---

## APIキー

APIキーをiPhoneアプリの中に直接埋め込まない。

```
悪い例

iPhoneアプリ
   ↓
AI API
   ↑
APIキー
```

アプリを解析されてAPIキーを抜かれる可能性がある。

基本的には、

```
iPhoneアプリ
   ↓
自分のサーバー
   ↓
AI API
```

として、APIキーはサーバー側で管理する。

---

## APIの悪用

AI APIを使うアプリでは、悪意あるユーザーによる大量利用も考える。

対策として、

- ユーザーごとの利用制限
- Rate Limit
- 1回あたりの入力サイズ制限
- API利用量の監視
- 料金アラート
- 必要に応じた認証

などを設定する。

特にAI APIは、**大量利用されると料金が急増する可能性がある**。

---

## 個人情報

個人情報を扱うなら、

```
何を取得する？
なぜ取得する？
どこに保存する？
どれくらい保存する？
誰が利用できる？
削除できる？
```

を決める。

最も簡単な対策は、**必要なければ保存しないこと**。

App Storeでのプライバシー関連の申告内容と、実際のアプリのデータ処理も一致させる。

---

## AIを使って開発する場合

Claude CodeやCodexなどにコードを書かせても、**生成されたコードをそのまま信用しない**。

特に確認する場所は、

- APIキー
- パスワード
- 認証
- 権限
- 外部通信
- データ保存
- ユーザー入力
- ファイル操作

など。

「動いた」と「安全」は別。

---

## AIエージェント

AIエージェントには必要以上の権限を与えない。

```
ファイル操作
コマンド実行
ネットワークアクセス
API操作
```

などを全部許可すると、AIの誤操作や悪意ある入力による被害が大きくなる。

特に「全部許可」のような設定は慎重に扱う。

---

## プロンプトインジェクション

AIアプリでは、ユーザーの入力や外部Webページに悪意ある指示を混ぜられる可能性がある。

例えば、

```
ユーザー
 ↓
AI
 ↓
外部API
```

という構造の場合、ユーザー入力をAIが「単なるデータ」ではなく「実行すべき命令」として扱わないようにする。

AIに外部操作の権限を与えるほど重要になる。

---

## GitHub・開発環境

GitHubなどに、

```
APIキー
パスワード
秘密鍵
アクセストークン
個人情報
```

をアップロードしない。

`.env`などを使い、秘密情報をGit管理から外す。

また、

```
開発環境
    ↓
テスト用API・テストデータ

本番環境
    ↓
本番API・本番データ
```

と分ける。

---

## 外部ライブラリ

Swift Packageや外部SDKなどを使う場合は、それらにも脆弱性が存在する可能性がある。

AI関連ライブラリを含め、使用しているパッケージを定期的に確認する。

---

## Web公開

ここは今回の動画で特に重要な部分。

```
iPhoneアプリ
   ↓
自分のサーバー
   ↓
インターネット
```

となると、サーバーへの攻撃を考える必要がある。

さらに、

- データベース
- ログイン
- 個人情報
- AI API
- 課金
- 管理画面

などが増えるほど難しくなる。

**AIにWebアプリを作らせて、そのまま公開するのは避ける。**

---

## App Store審査

Appleの審査は重要だが、

**「審査を通った＝完全に安全」ではない。**

Appleの審査とは別に、

- サーバーの脆弱性
- APIキーの漏洩
- APIの不正利用
- データベースの設定
- 大量アクセス
- AI API料金の暴騰

などは開発者側で管理する必要がある。

---

## AIアプリのコスト

AI APIを使うなら、セキュリティだけでなく料金も設計段階で考える。

```
1回いくら？
↓
1ユーザーで最大何回？
↓
1日最大いくら？
↓
全ユーザーで最大いくら？
```

という形で計算する。

---

## 障害への対応

外部APIは停止する可能性がある。

```
正常
→ 普通に処理

通信失敗
→ エラー表示

タイムアウト
→ 再試行または終了

API停止
→ アプリが落ちずに処理
```

というように、異常時も考えておく。

---

## 「漏れない」より「漏れても被害を小さく」

今回のセキュリティの話で最も重要な考え方。

```
重要情報
   ↓
AI
```

ではなく、

```
重要情報
   ↓
必要な部分だけ取り出す
   ↓
AI
```

とする。

さらに、重要データとAIを動かす環境を分離する。

**重要な情報をそもそもAIに触らせない**のが強い。

---

## 最初は小さく作る

最初から、

```
iPhone
 ↓
サーバー
 ↓
データベース
 ↓
AI
 ↓
ログイン
 ↓
課金
```

と全部入れない。

まず、

```
iPhone
 ↓
最小限のAPI
 ↓
結果
```

程度で作り、動作・安全性・料金を確認してから機能を増やす。

---

# 最終的に覚えておくこと

iPhoneアプリだから特別に危険というわけではない。

重要なのは、

**「アプリの外に何を出すか」**

です。

特に、

> **iPhone内だけで完結 → 比較的簡単**

> **外部APIを使う → APIの安全性・料金を確認**

> **自分のサーバーを使う → サーバーのセキュリティも必要**

> **個人情報・課金・AIまで扱う → 本格的なサービス設計が必要**

という考え方で進めればいい。

今回の動画を踏まえるなら、アプリ制作で最初に確認する項目は **「このアプリは外部に何を送るのか？」**。ここを明確にしてから設計を始めるのが重要。
