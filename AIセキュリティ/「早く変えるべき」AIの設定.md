1. AIのモデルを確認する

ChatGPTなどの有料プランでも、常に最も高性能なモデルが使われているとは限らない、という指摘。

動画では「せっかく課金しているのに自動選択のまま、意図せず軽いモデルを使っている人がいる」と説明しています。

ただし、これはサービスや時期によってモデル選択の仕様が変わるので、「有料＝自動的に最強モデルではない」という程度に理解するのがよいです。

2. メモリ・過去チャット参照に注意

これはかなり重要です。

AIに、

「過去の会話を参考にする」  
「自分について覚えていることを利用する」

という機能を許可すると、便利になる一方で、現在の会話とは関係ない過去の情報が回答に出てくる可能性があります。

特に仕事の画面を他人に見せながらAIを使う場合、

「以前の仕事でこういう情報がありましたよね」

などとAIが過去情報を持ち出すと困る場合があります。

つまり、

便利さ ↔ 情報の分離

のトレードオフです。

3. 「AIの学習に使う」設定を確認する

動画の中で最も重要な初級編はここです。

ChatGPTやCursorなどには、利用データをサービス改善に使用するかどうかの設定があります。

ただし、動画の

「オンなら全部AIの学習に吸収される」

という説明はかなり単純化されています。

実際にはサービスごとに、

・学習への利用  
・ログ保存  
・人間によるレビュー  
・企業向けデータ保護  
・一定期間後の削除  
・オプトアウト

などが別々に設定されています。

したがって、「AIには絶対に機密情報を入れない」が一番単純で安全な原則です。

4. 企業では「どのAIを使うか」より「どの契約・環境で使うか」が重要

動画の中盤の話はここが本質です。

例えば、

個人向けChatGPT  
↓  
企業向けChatGPT  
↓  
Azure / AWS / Google Cloud経由  
↓  
ローカルLLM

では、データ管理・契約・保存場所・学習利用・アクセス制御などが変わります。

そのため企業では、

「ChatGPTだから危険」  
「Claudeだから安全」

という単純な話ではありません。

むしろ、

「どのプラン・契約で」  
「どこにデータが送られ」  
「何に使われ」  
「誰がアクセスでき」  
「どの国に保存され」  
「削除できるのか」

を見る必要があります。

5. AIエージェントに「パソコンを操作する権限」を与えると危険度が一気に上がる

ここが今回の動画で一番重要だと思います。

普通のChatGPT：

ユーザー → 質問 → AI → 回答

AIエージェント：

ユーザー → 指示 → AI → ファイル操作・プログラム実行・Web操作など

になります。

後者ではAIが「答えるだけ」ではなく「実際に何かをする」ので、失敗したときの被害が大きくなります。

例えば、

「このフォルダを整理して」

という指示に対してAIが誤判断すると、ファイルを移動・変更・削除する可能性があります。

だから、

「AIに何ができるか」

よりも、

「AIに何をさせてよい状態なのか」

が重要になります。

6. Cursor / Claude Code / Skillsなどは「権限」が最大の注意点

動画後半の重要部分です。

例えばAIに、

「このプロジェクトを修正して」

と頼むだけなら比較的安全ですが、

「自動実行」  
「確認を全部スキップ」  
「ファイル操作を許可」  
「コマンド実行を許可」

などを組み合わせると、AIがかなり自由に動けるようになります。

特に危険なのは、

「自分の大事なファイルがある場所を作業ディレクトリにする」

こと。

動画で言っている「深い階層で開け」というのは、要するに、

AIに必要以上の範囲を見せるな

ということです。

例えば、

悪い例：

デスクトップ  
└── AIプロジェクト  
└── 個人書類  
└── 写真  
└── その他重要ファイル

ここをAIに丸ごと操作させる。

より安全なのは、

AI_Work  
└── Project_A  
├── src  
├── assets  
└── test

のように、AIに触らせていい領域を独立させる方法です。

7. Skillsは「便利な命令セット」だが、入手元に注意

動画の最後の話です。

Skillsは簡単に言えば、

「この作業をするときは、この手順・ルールで動いて」

という作業手順をAIに渡して再利用する仕組みです。

これはかなり便利ですが、外部から入手したSkillを無条件に実行するのは危険です。

なぜならSkillの中に、

・ファイル操作  
・コマンド実行  
・外部通信  
・データ送信

などの処理が含まれている可能性があるからです。

つまり、

「便利そうだからインストール」

ではなく、

「中身を確認してから使う」

が基本になります。

そして動画全体を一言でまとめるなら、

「AIを使うな」ではなく、

「AIに渡す権限を最小限にしろ」

です。

これは以前話していたアプリ制作にもそのまま当てはまります。

あなたがアプリをAIに作らせる場合も、

「APIを使っているか」  
→「どこに接続するか」  
→「何のデータを送るか」  
→「APIキーはどこにあるか」  
→「AIや外部サービスに何を渡すか」  
→「ローカルだけで完結できるか」

を確認する、という考え方になります。

特に今回の動画で、かなり重要なのは「AIそのものが危険」というより、AIが高性能になるほど、

「データ権限」  
「ファイル権限」  
「実行権限」  
「ネットワーク権限」

の4つが重要になる、という点です。

そしてこれは、以前話していた「APIに依存しないアプリ設計」ともつながっています。AI/API/Skills/エージェントを便利に使いながらも、いつでも切り離せる構造にしておく、という考え方です。
