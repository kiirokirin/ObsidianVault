[[AIブラウザのセキュリティリスクについて]]
**1. AIチャットへの情報投入対策**

- ChatGPT、Gemini、Claudeの学習利用（オプトアウト）をOFF
- 個人情報は入力しない
- パスワード、APIキー、秘密鍵は入力しない
- 会社の機密情報は社内ポリシーに従う

これは「AIサービス提供者への情報漏洩対策」です。

---

**2. AIエージェントの暴走対策**

動画で強調されていた部分です。

- 自動実行をOFF
- AIが何をするか毎回確認
- 作業フォルダを限定
- 不要な権限を与えない

例えば、

```
C:\Users\
```

全部を触らせるのではなく

```
C:\AI\_Agent_Test
```

だけを触らせる。

---

**3. プロンプトインジェクション対策**

これが「AIエージェントの乗っ取りを防ぐ」に相当します。

動画の主張は、

「AIを騙す攻撃は既に成立している」

です。

対策としては

- 信頼できないサイトを読ませない
- AIブラウザに重要アカウントでログインしない
- Web検索＋自動実行を避ける
- 許可ドメイン機能があれば使う

です。

---

**4. 被害が起きても復旧できるようにする**

ここは動画では軽く触れられただけですが重要です。

- Git
- バックアップ
- 開発コンテナ
- 仮想環境

を使う。

つまり

```
予防
↓
被害発生
↓
即復旧
```

の考え方です。

---

あなたの場合だと、

現在の

```
MAX/MSP
Python
Gemini CLI
```

環境で本当に注意すべきなのは、

**APIキーを作業フォルダに平文保存しないこと**

です。

動画で言っていた

```
.env
APIキー
認証情報
```

が漏れるケースはまさにここです。

もし将来、

「Gemini CLIにWebを検索させながら自動実行」

をやり始めたら、動画で説明されているプロンプトインジェクションのリスクが現実的になります。

逆に今の段階なら、

- 自動実行しない
- Gitで管理
- APIキーを慎重に扱う
- 作業フォルダを限定
